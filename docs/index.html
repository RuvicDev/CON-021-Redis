¿Qué es y para qué sirve?

El conector Redis permite que el agente de Ruvic lea y escriba claves en tu servidor Redis. A diferencia de los conectores de bases de datos del catálogo, este conector sí escribe. Una vez configurado, puedes pedirle al agente cosas como:

  • “¿Cuál es el valor guardado en la clave sesion:usuario_42?”
  • “Guarda esta configuración en caché con el nombre config:tema, que expire en 1 hora.”
  • “Lista todas las claves que empiezan con carrito: para ver cuántos carritos activos hay.”

Operaciones soportadas:

Operación Qué hace
redis.read Lee el valor y el tiempo de expiración (TTL) de una clave
redis.write Escribe (o sobrescribe) una clave, con expiración opcional
redis.list_keys Lista las claves que cumplen un patrón, sin bloquear el servidor
Este conector escribe redis.write sobrescribe el valor de la clave indicada. Se recomienda restringir el acceso del usuario dedicado a un patrón de claves específico (ver sección 3) en vez de dar acceso a todo el servidor.

Prerrequisitos

  • Un servidor Redis 6.0 o superior (para poder usar ACL con restricción por patrón de claves; versiones anteriores solo soportan contraseña compartida).
  • Acceso administrativo al servidor (para crear el usuario ACL), solo durante la configuración inicial.
  • Acceso de red desde la plataforma Ruvic al servidor Redis (host y puerto alcanzables; regla de firewall o lista de IPs permitidas si aplica).
  • Los datos de conexión: host y puerto (por defecto 6379).

Configuración en el fabricante

Vas a crear un usuario ACL restringido a un patrón de claves para Ruvic. No uses la cuenta default ni compartas la contraseña maestra del servidor: un usuario dedicado limita el radio de acción del agente a solo las claves que le corresponden.

  1. Conéctate al servidor como administrador.

    Usa redis-cli con la contraseña maestra:

    redis-cli -h TU_HOST -p 6379 -a TU_CONTRASEÑA_ADMIN
  2. Crea el usuario restringido para Ruvic.

    Elige una contraseña fuerte (mínimo 16 caracteres, generada aleatoriamente) y guárdala: la usarás en el formulario de Ruvic (campo Contraseña). El ejemplo restringe el acceso a claves con el prefijo ruvic: — ajusta el patrón a tu convención de nombres:

    ACL SETUSER ruvic_agent on >CAMBIA_ESTA_CONTRASEÑA ~ruvic:* +get +set +scan +ttl +ping
    Nota El patrón ~ruvic:* limita al usuario a claves que empiecen con "ruvic:". Los comandos +get +set +scan +ttl +ping son exactamente los que usa el conector; no se otorgan otros comandos.
  3. Persiste la configuración ACL.

    Si tu servidor usa un archivo users.acl, guarda los cambios para que sobrevivan a un reinicio:

    ACL SAVE

    Si no tienes un archivo ACL configurado (aclfile en redis.conf), el usuario se pierde al reiniciar Redis; considera configurarlo para uso en producción.

  4. Habilita el acceso de red desde Ruvic.

    Si tu Redis restringe conexiones por IP (habitual en producción), permite la IP de la plataforma Ruvic:

    • Servidor propio: regla de firewall del sistema operativo para el puerto 6379, y verifica que bind en redis.conf permita conexiones remotas (no solo 127.0.0.1).
    • Redis administrado (ElastiCache, Redis Cloud, etc.): agrega la IP en el security group o en la lista de redes autorizadas de la consola del proveedor.
    [ Captura: regla de firewall / security group con la IP de Ruvic — reemplazar por assets/img/redis-firewall.png ]
  5. Verifica el usuario desde fuera del servidor.

    Desde una máquina distinta al servidor (idealmente con salida de red similar a la de Ruvic):

    redis-cli -h TU_HOST -p 6379 --user ruvic_agent -a TU_CONTRASEÑA PING

    Si responde PONG, el fabricante quedó listo. Anota estos valores para la siguiente sección: host, puerto, usuario y contraseña.

Permisos requeridos

Principio de mínimo privilegio: el usuario de Ruvic solo necesita estos comandos, y solo sobre el patrón de claves que le corresponde. No otorgues +@all, +flushall, +flushdb ni acceso sin restricción de claves (~*).

Comando Para qué sirve
GET Leer el valor de una clave (redis.read)
SET Escribir una clave, con o sin expiración (redis.write)
SCAN Listar claves que cumplen un patrón sin bloquear el servidor (redis.list_keys)
TTL Consultar el tiempo restante de expiración de una clave (parte de redis.read)
PING Verificar la conexión (botón "Probar conexión")

Además de los comandos, la ACL debe restringir las claves accesibles con un patrón (ej. ~ruvic:*). Sin esta restricción, el usuario puede leer y escribir cualquier clave del servidor, aunque los comandos estén limitados.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Redis y pulsa Configurar. Diligencia el formulario con los valores que obtuviste en la sección anterior:

Campo del formulario Valor
Host Hostname o IP del servidor (ej. cache.empresa.com)
Puerto 6379 (salvo configuración distinta)
Usuario ruvic_agent (déjalo vacío si tu servidor solo usa contraseña, sin ACL)
Contraseña La contraseña del paso 2. Se guarda cifrada como secreto: la interfaz no volverá a mostrarla
Número de base de datos Opcional; 0 por defecto (índice lógico de Redis, no confundir con una base de datos relacional)
Timeout de conexión Opcional; 10 segundos por defecto

Guarda y pulsa Probar conexión — la plataforma se conectará a tu servidor y confirmará que las credenciales y la red funcionan.

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: “Conexión exitosa a tu-host:6379/db0”. La tarjeta del conector cambia a estado Configurado.

  2. Automatización mínima de prueba.

    Abre una conversación nueva con el agente y pídele: “Guarda la clave ruvic:prueba con el valor hola, que expire en 60 segundos, y luego léela para confirmar.” El agente debe escribir la clave y leer de vuelta el mismo valor. Si lo hace, el conector quedó operativo de punta a punta.

Solución de problemas

Mensaje / síntoma Causa probable y solución
“Autenticación fallida: usuario o contraseña inválidos” Contraseña mal copiada, usuario inexistente, o el usuario ACL no persistió tras un reinicio (falta ACL SAVE o el aclfile no está configurado). Reintenta el paso 2 de la sección 3.
“No se pudo conectar … (timeout)” La plataforma no alcanza el host/puerto. Revisa el paso 4 (firewall / security group / bind en redis.conf) y que el host no sea localhost (debe ser accesible desde Ruvic, no desde tu equipo).
El agente puede leer pero “no tiene permiso” al escribir (o viceversa) La ACL del usuario no incluye el comando necesario. Revisa que el paso 2 de la sección 3 haya incluido +get +set +scan +ttl +ping completos.
“La clave existe pero no es de tipo string” El conector solo lee/escribe claves de tipo string (WRONGTYPE). Si la clave es un hash, lista o set, no es compatible con este conector.
El conector aparece “Sin configurar” tras guardar El campo Host quedó vacío (es el único obligatorio). Ábrelo de nuevo y complétalo.

Preguntas frecuentes y notas de seguridad

¿El agente puede leer o modificar cualquier clave del servidor?

Solo si tú lo permites en la ACL. Con el patrón ~ruvic:* del ejemplo, el agente queda limitado a las claves con ese prefijo. Sin ACL (servidores anteriores a Redis 6, o usuario default), no hay restricción por clave: cualquier credencial válida tiene acceso a todo el keyspace.

¿Dónde queda guardada la contraseña?

Como secreto en el almacén de credenciales de la plataforma, asociado a tu usuario. La interfaz nunca vuelve a mostrarla; solo indica “definida”. Para cambiarla, escribe una nueva en el formulario; para conservarla al editar otros campos, deja el campo vacío.

Rotación de credenciales

Recomendado cada 90 días o según tu política: cambia la contraseña con ACL SETUSER ruvic_agent >NUEVA_CONTRASEÑA, actualízala en el formulario del conector y pulsa Probar conexión.

¿Qué hago si la contraseña se compromete?

  1. Desactiva el usuario de inmediato (ACL SETUSER ruvic_agent off) o cambia su contraseña.
  2. Revisa ACL LOG para ver intentos de acceso denegados recientes.
  3. Actualiza la nueva contraseña en el formulario del conector.

¿Por qué no hay un comando para borrar claves?

Por diseño: limitar las operaciones a lectura y escritura (con TTL) reduce el riesgo de que el agente elimine datos por error. Si necesitas que una clave desaparezca, usa write_key con un ttl_seconds corto para que expire sola.

Buenas prácticas Usa siempre un usuario ACL restringido a un patrón de claves específico; nunca compartas la contraseña maestra del servidor con el conector; separa el namespace de Ruvic (ej. prefijo ruvic:) del resto de tu aplicación; y evita compartir la contraseña por canales no seguros.
